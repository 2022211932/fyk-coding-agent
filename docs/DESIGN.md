# FYK Coding Agent 设计说明

本文用于解释核心机制和设计取舍，重点对应面试中“为什么这样运转”的问题。

## 目标与非目标

目标是实现一个代码量可控、能够真实完成编程任务、每层都可以解释的 Coding Agent。项目不追求兼容所有模型厂商，也不实现 IDE 图形界面、多 Agent 调度或远程执行集群。

选择 Python 标准库有三个原因：减少框架隐藏逻辑；便于审计实际发送的 HTTP 请求；评委可以直接从入口跟踪到每个本地副作用。

## 状态机

一次任务有四种状态：

```text
READY -> REQUESTING_MODEL -> EXECUTING_TOOLS -> REQUESTING_MODEL
                          \-> COMPLETED
                          \-> STEP_LIMIT
                          \-> MODEL_ERROR
```

`CodingAgent.run` 是唯一控制循环。模型只负责提出工具调用，不能直接触碰文件或进程。本地 `ToolRegistry` 是产生副作用的唯一入口。

## 对话协议不变量

1. 第一个消息始终是系统提示，第二个消息始终是原始用户任务；
2. 含 `tool_calls` 的 assistant 消息必须位于对应 tool 消息之前；
3. 每个 tool 结果使用模型提供的 `tool_call_id` 回填；
4. 工具失败也必须产生 tool 结果，避免对话协议断裂；
5. 模型没有返回工具调用时才把文本视为最终回答；
6. DeepSeek 返回的 `reasoning_content` 随 assistant 消息保留，但不展示或写入工具结果。

## 为什么使用原生 Tool Calling

模型原生 tool calling 提供稳定的工具名、调用 ID 和 JSON 参数，避免从 Markdown 代码块中猜测命令。项目仍自行完成 schema 定义、参数解析、本地执行、结果序列化和循环控制，因此没有把 Agent 逻辑交给 API 服务端。

## 上下文管理

不引入 tokenizer，使用序列化后的字符数作为保守估算。压缩时不逐条删除消息，而把一次 assistant 回复和其后的 tool 结果视为完整块，从旧到新删除。这样不会留下无法被 API 接受的孤立 tool 消息。

始终保留系统提示和原始任务。被删除内容不做模型摘要，因为摘要会增加额外调用、成本和新的幻觉来源；需要精确信息时，系统提示要求模型重新读取文件。

## 工具边界

`Workspace.resolve` 对所有模型提供的路径执行以下检查：

- 只接受相对路径；
- `Path.resolve` 后必须仍属于工作区；
- 拒绝 Git 元数据、Agent 内部状态和凭据类文件；
- 写入不能以工作区根目录本身为目标。

`write_file` 使用同目录临时文件加 `os.replace`，避免进程中断留下半个文件。`edit_file` 要求精确匹配数等于模型声明值，防止一次替换误伤多处相似代码。

## 审批模型

读取操作默认自动执行；文件修改、建目录和命令执行统一视为有副作用，默认请求批准。审批发生在工具参数解析之后、执行之前。`--yes` 是显式用户选择，只适合受控演示工作区。

命令执行本身是必要能力，不能用简单黑名单完整判断风险，因此安全边界由“工作目录限制 + 环境变量清理 + 超时 + 人工审批”共同构成。

## 撤销模型

文件工具在写入前把“相对路径、是否存在、原始字节”追加到 `.fyk-agent/snapshots.jsonl`。撤销已有文件时恢复原字节；撤销新文件时删除该文件。

没有宣称对 `run_command` 提供事务回滚，因为任意命令可能修改多个文件甚至调用外部服务，伪装成可回滚反而不安全。

## 错误处理

| 错误 | 处理方式 |
| --- | --- |
| 工具名不存在 | 返回 `unknown_tool` 给模型 |
| 参数 JSON 非法 | 返回 `invalid_tool_call` 给模型 |
| 路径越界 | 返回 `WorkspaceError`，不执行 |
| 用户拒绝 | 返回 `rejected`，模型可改方案 |
| 命令非零退出 | 保留 stdout、stderr 和退出码 |
| 命令超时 | 返回 `timed_out=true` |
| 429/部分 5xx | 指数退避重试 |
| 达到轮数上限 | 以 `step_limit` 明确终止 |

## 已知边界

- 只直接处理 UTF-8 文本；
- 字符预算不是精确 token 预算；
- shell 命令的任意副作用无法完全沙箱化；
- 当前任务之间不共享对话，只共享用户可查看的事件日志和文件状态；
- 快照适合轻量代码文件，不适合大二进制资产。

这些边界是主动取舍：在考核项目中，明确而诚实的边界比未经验证的复杂功能更容易审计和辩护。
